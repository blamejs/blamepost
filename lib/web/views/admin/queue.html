Retrying reaches every entry whose moment has arrived, and the ones that answer transiently again go back with their attempt count intact, so the retry budget still runs out on schedule.

Cancelling shows you what it is about to erase and asks for the count and a reason before it does. The count is taken again when you send it, so a message that reaches its recipient while you are reading stops the whole cancellation rather than being quietly left out.

A cancelled message whose sender is a mailbox on this server gets a delivery report, so nobody here is left believing a message went out when it did not. A cancelled message whose sender this server hosts nothing at does not: that address arrived on the wire and whoever sent the message chose it, so writing to it would mail a stranger's choice of address from this server. Mail arriving through a forwarding alias is the ordinary case, and mail sent under a stolen credential is the case you are most likely here for. The audit trail records which senders were told and which were not, so you can tell anyone who needs to know.
